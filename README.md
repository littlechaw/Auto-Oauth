# Auto OAuth

独立的 Chrome OAuth 授权扩展，只处理已有 OpenAI 账号的授权

## 使用

1. 在 `chrome://extensions/` 启用开发者模式。
2. 点击“加载已解压的扩展程序”，选择 `auto-oauth` 目录。
3. 侧边栏分为“授权”和“设置”两页，“授权”页顶部“账号”行显示当前账号邮箱，点“改”展开账号信息文本域，粘贴 `邮箱----密码----https://2fa.example/...----其他信息` 一类的重复分隔符内容，或 `邮件：name@example.com 密码：your-password` 这类带字段名的内容，然后点击“解析账号信息”。扩展会依次校验邮箱、读取密码，并仅在重复分隔符格式的第三段为完整 HTTPS 2FA 地址时替换“验证码”区的 2FA 地址框；第四段及后续内容会忽略。邮箱中的 `\@` 会按 `@` 处理。未提供地址时会保留现有地址。点击“访问”会在新标签页打开该地址，原始账号信息不会保存。
4. CPA、SUB2API 与 HeroSMS API Key 在“设置”页填写，可同时保留，无需清空任一方。
5. 点击底部的“授权 CPA”或“授权 SUB”，扩展会打开对应平台的官方 OpenAI 授权页，并自动点击“使用其他账号”、填写并提交登录信息，再确认 OAuth 授权。CPA 授权成功后，侧边栏会显示“设置100权重”按钮，点击后扩展会找到本次新保存的 CPA 账号（按授权邮箱和创建时间定位）并设置优先级 100、权重 1；若点击时 CPA 尚未保存完账号，会自动轮询等待。授权请求由 CPA 本体校验“CPA 管理密钥”，而“设置100权重”经由管理面板校验，两者密钥不同时请在“面板 Admin Key”中单独填写（留空则使用“CPA 管理密钥”）。
6. 可直接在“授权”页的“验证码”输入框粘贴验证码，输入框发生变更时自动暂存；只有授权页出现验证码输入框时才自动填写并提交一次。提交后 4 秒仍停留在验证码页时，扩展会清空验证码并停止自动点击，供你修改后重新填写。安全验证仍需在官方页面完成。回调到 `http://localhost:1455/auth/callback` 后，扩展会自动提交 CPA 或向 SUB2API 创建 OAuth 账号。侧边栏底部的状态栏常驻显示进度（登录 → 验证 → 手机 → 授权 → 提交）和最新状态，出错时对应步骤标红。
7. “手机接码（HeroSMS）”为手动模式：在“设置”页填写 HeroSMS API Key 后，可在“授权”页点“查余额”；点击“获取最便宜号码”会在候选国家中按 OpenAI 服务的最低价自动下单，并每 5 秒轮询验证码（最多 3 分钟），号码与验证码均需自行复制使用。收到验证码后点“完成订单”，未收到可“取消退款”。轮询期间需保持侧边栏打开。授权页号码被占用或异常时，自动化会暂停点击并在侧边栏提示；点击“换号重试”会先取消旧订单（下单 2 分钟内平台拒绝取消时，旧订单会保留在“重试取消”列表中，稍后点“重试取消”退款）再下单新号码，清除授权页旧号码并粘贴新号码后自动化会自动继续。

配置保存在当前浏览器的扩展本地存储中。管理密钥和密码不会写入日志或状态信息。
